## A fallback-demo safety finding: do not invoke the Compiler or Sender Lambda directly

An earlier draft of this kit proposed showing a direct, on-camera invocation of the deployed
Compiler Lambda as the fallback demo's "genuinely live" privacy-boundary moment. On inspection
of `functions/compiler/handler.py` and
[05-privacy-compiler-and-shareable-view.md](../architecture/05-privacy-compiler-and-shareable-view.md),
that is not safe to do cleanly, for two independent reasons:

1. **`CompileViewCommand.requested_facts` is caller-supplied fact IDs, not generated by the
   compiler.** The application layer — not the compiler — is what "generates candidates from
   active case facts" (§ Compile command). A hand-typed invocation payload for a video would
   have to either name fact IDs from a real, resident-approved case, or invent plausible-looking
   ones. The latter is exactly the fabricated application state we were told to avoid.
2. **A successful `CompileView` call is not read-only.** It commits a new immutable
   `ShareableCaseView`, a current-pointer update, and an audit entry in one DynamoDB transaction,
   and may write a safe evidence derivative to the export S3 bucket first. It is real state
   mutation in the live account, not a safe inspection.

Because no case currently exists in the live Core table with real, mandate-approved facts (the
Monitor agent that would create one depends on the blocked AgentCore stack), the only two
outcomes of a direct call are: a fabricated-looking payload that misrepresents how the system
actually decides what's real, or a hollow `CASE_NOT_FOUND_OR_FORBIDDEN` deny that demonstrates
nothing. Neither is worth the risk.

The **Sender Lambda has the identical problem in the opposite direction**: its one operation,
`SendAction`, requires a real prior `APPROVED` execution row (`functions/sender/handler.py`,
[ADR-025](../adr/ADR-025-one-deliberate-ses-attempt.md)). No such execution exists yet either.
The SES canary already verified live was almost certainly a **direct SES `SendEmail` API call**
against the verified identity/configuration set — not a call through this Lambda — and that
remains the right thing to re-run on camera, precisely because it needs no case state at all.

**What to show live instead:** the deployed **Reset Lambda** (`functions/demo_reset/handler.py`).
It is built for exactly this. It is an operator action with no API Gateway route or Function URL
— unreachable from the application, invocable only directly and deliberately
(deployment contract § 19, § 25). Its payload is `{namespace, confirm, seed_version?,
idempotency_key?}` — a namespace, a literal confirmation string, and an optional seed version,
nothing case-shaped. It is replay-safe by design (ADR-031) and returns only safe operational
metadata: a reset id, item counts, a `replayed` flag, a duration — never evidence text, an
address, or a token. It is already the sanctioned pre-demo step
(`uv run chorus-demo reset --namespace DEMO --confirm "RESET DEMO" --seed elevator/v1"`), so
running it on camera is not a novel or improvised path — it is the same command already used to
prepare every rehearsal.

So the fallback script's two genuinely-live-AWS beats are: **(a)** the Reset Lambda reseeding the
`DEMO` namespace live, and **(b)** the direct SES canary send with real Gmail delivery. Both need
zero fabricated case data and both are already-proven, repeatable operations.

## 1. Devpost copy

### Title

Ambient CHORUS

### Tagline — recommended

**"One complaint is easy to ignore. Chorus finds the pattern."** (the project's own established
line — states the actual mechanism, not a genre label.)

Alternates: *"Privacy-preserving investigation for the problem your building keeps having."* /
*"The case-building agents that never see more than they're allowed to."*

### Inspiration

Tenant and community complaint systems fail for a structural reason, not a technology reason:
every report arrives alone. A resident emails the property manager about the elevator; the
manager has no way to see that five other households sent variations of the same complaint over
three weeks, because those messages live in five separate inboxes, texts, and hallway
conversations. The person who could aggregate that pattern is the same person with the least
power to act on it — and the evidence that would make the case undeniable is exactly the
evidence residents are, correctly, wary of handing to a system they don't control. Ambient
CHORUS is built around a hard architectural line between *finding the pattern* and *deciding
what may leave the building*, with a deterministic authority — not a language model — on the
disclosure side of that line.

### What it does

CHORUS watches a community message feed (a synthetic feed in V1, standing in for a channel like
a resident portal) for fragments describing the same unresolved problem. In the demo scenario,
four residents send messages about a broken elevator over time, mixed with unrelated chatter.

1. **Intake** — the Monitor agent proposes candidate facts and a possible recurring-issue link;
   it cannot grant disclosure.
2. **Private mandates** — each resident sees exactly the facts extracted from their own
   messages and decides, fact by fact, what may be shared, and whether their identity may be
   attached — explicit, versioned, revocable grants, never inferred.
3. **Investigation** — the Investigator/Skeptic agent checks independence, flags contradictions,
   classifies evidence; it cannot expand what's shareable either.
4. **Privacy compilation** — a deterministic, LLM-free compiler evaluates every fact against its
   mandate, purpose, and destination, and produces an immutable `ShareableCaseView`: the
   minimum-necessary, re-identification-checked slice of the case safe to leave the system.
5. **Action & approval** — the Action Coordinator receives *only* that view and drafts a cited
   request to the property manager; a human approves the exact rendered email before anything
   sends.
6. **Follow-through** — a manager commitment is extracted, scheduled as a real deadline, and
   verified by a background watcher; `ACTIONED` never becomes `RESOLVED` on its own.

### How we built it

- **Reasoning layer** — Strands Agents SDK for all three agents (`runtimes/monitor`,
  `runtimes/investigator`, `runtimes/action`); Amazon Bedrock, Nova 2 Lite
  (`amazon.nova-2-lite-v1:0`, temperature 0); three separate Bedrock AgentCore Runtime resources,
  each with its own IAM role, isolated VPC subnet, IAM-based inbound auth, no NAT/internet.
- **Deterministic backbone** — explicit Python application-code orchestration (no
  graph/swarm/workflow abstraction; agents never call each other); a 22-step, LLM-free privacy
  compiler as the sole creator of `ShareableCaseView`; three DynamoDB tables (Core, Shareable,
  Audit); SES v2 through a dedicated sender with a one-deliberate-attempt send fence; EventBridge
  Scheduler for real commitment deadlines.
- **Infrastructure & app layer** — AWS CDK v2 (Python), 11 stacks wired by real resource ARNs
  with explicit dependencies, pinned to `us-east-1`; React + Vite (TypeScript) frontend with
  exactly three UI surfaces; FastAPI backend (`apps/api/chorus_api`) on Lambda via Mangum behind
  API Gateway; a dedicated, IAM-isolated Reset Lambda with an atomic mutation interlock.

### Challenges we ran into

- Making disclosure authority live entirely outside the model — the Action agent's IAM role has
  no read access to Core DynamoDB or the private evidence bucket at all.
- Getting deterministic disclosure right under real edge cases (revoked mandates racing an
  in-flight compile, forwarded duplicate evidence inflating corroboration) — now a named,
  ordered, fail-closed check per case, 22 steps deep.
- SES send safety — the naive "approve then send" ordering can't be built against an immutable
  execution record; redesigned around a fence that's honest about what it can't prevent and an
  explicit `SEND_UNKNOWN` state instead of guessing ([ADR-025](../adr/ADR-025-one-deliberate-ses-attempt.md)).
- Reset concurrency — a demo reset racing a live send or scheduled event is exactly the bug that
  looks fine in rehearsal and corrupts state on camera; fixed with an atomic reset-lock condition
  on every DEMO mutation ([ADR-031](../adr/ADR-031-demo-reset-mutation-interlock.md)).
- A live-only IAM defect — the first real deploy failed because VPC-attached Lambdas lacked
  permission for the ENI lifecycle operations Lambda's own service performs on their behalf; CDK
  synth and offline review both looked correct. Found and fixed during Phase 11
  (`infra/cdk/network_support.py`).
- AWS account provisioning, not code, is the current bottleneck: AgentCore quotas remain 0/0/0
  and Nova 2 Lite invocation is blocked account-wide; an AWS Support case is open and escalated.

### Accomplishments we're proud of

- Seven of eleven CDK stacks independently deployed and verified live in `us-east-1`.
- A real SES identity, verified and bound to a configuration set, with a live canary and
  confirmed delivery to a real Gmail inbox.
- A deterministic privacy compiler with a fully specified, documented 22-step evaluation order.
- 31 accepted ADRs recording the hard calls, not written after the fact.
- 227 backend test modules (unit, contract, Hypothesis property-based) plus 19 frontend test
  files, including dedicated privacy-isolation and stale-conflict tests.
- Found and fixed a real AWS-only IAM defect during live deployment.
- Three Strands-SDK agent runtimes, each with its own AgentCore runtime, endpoint, IAM role, and
  isolated VPC subnet — code-complete and offline-synth-validated, pending only the open quota
  case.

### Judge-facing differentiation

1. The disclosure authority is not the model — a separate, deterministic, LLM-free Lambda is the
   only code path that can create a shareable view.
2. Agents don't pass private context to each other by convention — they can't, by IAM. The
   Action Coordinator's role has zero read access to Core DynamoDB or the private evidence
   bucket.
3. Independent skepticism is a separate agent, not a second pass of the same one — corroboration
   (≥2 independent sources) and aggregate privacy (≥3 contributors) are different thresholds
   enforced by different code paths.
4. Every external action requires one-use human approval bound to the exact rendered content —
   approval authorizes one immutable send attempt of a specific hash, not a standing permission.
5. Least-privilege isolation runs all the way down — three agents, three IAM roles, three
   isolated VPC subnets with no NAT/internet; a reset principal scoped to the DEMO namespace
   only; a sender that cannot read the private bucket; a compiler that cannot call SES.

### What we learned

Least-privilege IAM has to be validated against the real AWS control plane, not just CDK synth.
Deterministic authorization has to be architected as a separate system from the start, not
retrofitted onto an agent pipeline. For an agentic hackathon build, AWS account provisioning can
be the actual critical path, independent of the engineering. Grounding matters more than
prompting for anything with legal or scheduling weight — we hard-reject relative/weekday date
phrasing from LLM-extracted commitments rather than trust a model to convert "Wednesday" into a
real instant ([ADR-021](../adr/ADR-021-action-grounding-and-caveats.md),
[ADR-027](../adr/ADR-027-commitment-extraction-grounding-and-authority.md)).

### What's next

Resolve the AgentCore/Bedrock quota case and run the full pipeline live end to end; confirm and,
if needed, deploy the Application, Inbound, and Observability stacks; expand past the single
synthetic scenario and destination type once the boundary is demonstrated live under real agent
execution; harden beyond the single `DEMO` namespace toward multi-tenant isolation and
production identity.

### Track fit — Good Neighbor Agents

Ambient CHORUS targets a specific kind of neighbor problem: individually powerless people who
collectively have a case, where the trust that makes collective action possible depends on
nobody's private report leaving their control without explicit, specific permission. The whole
architecture — independent verification before a case forms, per-fact resident-controlled
mandates, a deterministic compiler as the only path to external disclosure, and human approval of
the exact outbound message — targets that trust problem directly. It's an agent system whose job
is to be a good neighbor to the people whose data it holds, not just to automate a complaint
form.

## 5. Claim-safety guidance

Full audit table lives in the published Phase 13 kit artifact; the rules that matter most for
this recording pass:

- Never say "deployed on AgentCore" or "powered by Nova 2 Lite" as a live claim — both are
  code-complete and blocked, not live. Say so plainly.
- Never say "end-to-end deployed" without re-confirming the Application/Inbound/Observability
  stacks first (see the live/blocked table above).
- "Privacy preserving," "fully serverless," and "live AWS demo" are safe **only when scoped** to
  what's actually true — the deterministic backbone and the SES canary, not the full agent
  pipeline. Avoid the bare, unscoped phrases.
- Avoid "zero trust" and "production ready" outright; state the specific IAM/scope facts instead.
